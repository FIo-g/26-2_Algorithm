## 2. 문헌 수치와 우리 실험의 비교표

아래 가속비는 **각 원문 표 내부**에서 `Dijkstra 평균 질의 시간 / 해당 알고리즘 평균 질의 시간`으로 직접 계산했다. 문헌 사이의 시간을 나누지 않는다. 우리 측정은 Task 14의 `results/e2_summary.csv`가 생긴 뒤 채운다.

원문 위치:

- ALT: [PDF](https://www.microsoft.com/en-us/research/wp-content/uploads/2005/01/soda05.pdf) p.5 Table 1(그래프), p.6 §§8.1–8.3(조건·랜드마크), p.7 Table 2 및 §9(수치·지표). 실험은 128회 평균이며 3.06 GHz Pentium-4 환경이다. 논문의 Euclidean A* 비교에는 공격적인 휴리스틱 확대를 적용한 경우가 있으므로, 그 결과를 우리의 정확한 `직선거리/vmax` A*와 동등한 기준으로 옮기지 않는다.
- 서베이: [2015 v1 PDF](https://arxiv.org/pdf/1504.05140v1) p.21 §3.1.1(입력), p.22 Figure 7(시간 환산), p.23 Table 1(수치), pp.24–26(현실적 제약). Table 1은 Intel X5680 3.33 GHz 단일 스레드의 평균 질의 결과이고, Figure 7에는 다른 머신의 결과를 보정한 항목도 있다. 여기서는 Table 1의 지정 행만 옮겼다. 팀 계획의 “Bast 2016”과 관련된 서베이이지만, **직접 열람한 수치의 버전은 2015년 arXiv v1**이다. 출판본을 열람한 것처럼 쪽수를 표기하지 않는다.

비교할 때는 Python/C++ 등 구현 언어, 그래프 규모·도시, 거리/이동시간 가중치, 랜드마크 선택법, 질의 거리 분포, 평균/중앙값, 경로 복원 포함 여부를 함께 적는다. 우리 실험의 3회 중앙값과 문헌의 평균은 같은 통계가 아니다. 최종 발표에는 우리 머신에서 얻은 질의 가속비, 확정 노드 수, 전처리 비용을 우선 제시하고, 표 2는 경향의 일치 여부를 토론하는 데 쓴다. 전처리 시간이 큰 방법은 질의 횟수가 충분할 때만 이익일 수 있다.

## 3. 사용자 최적·시스템 최적과 공정성

각 운전자가 자신의 현재 이동시간만 최소화하는 선택과, 모든 차량의 이동시간 합을 최소화하는 배정은 다를 수 있다. 모두에게 같은 우회로를 추천하면 그 길의 혼잡이 달라져, 고정된 가중치에서 찾은 최단경로만으로 전체 교통 성능을 보장할 수 없다. 이는 우리의 E3 결과를 해석할 때의 한계다. E3는 외부에서 부여한 비용 스냅샷을 사용하며 차량들의 선택이 혼잡을 다시 바꾸는 피드백은 풀지 않는다.

[Roughgarden & Tardos, *How Bad Is Selfish Routing?*, JACM 49(2), 2002](https://www.cs.yale.edu/homes/lans/readings/routing/roughgarden-selfish-2002.pdf)는 비원자적 흐름의 균형과 총 지연의 최적값을 비교한다. §4, 인쇄 p.249의 조건은 `l_e(x)=a_e x+b_e`, `a_e,b_e≥0`이고, Theorem 4.5(인쇄 pp.251–252; PDF pp.16–17)는 이 모형에서 균형의 **총 지연 / 최적 총 지연 ≤ 4/3**을 보인다. 이 상한을 개별 차량의 손해, 임의 비선형 지연, 과도 상태의 SUMO, 또는 우리 E3 알고리즘 오차의 상한으로 사용하지 않는다.

후속 E4에서는 같은 수요·출발 시각·난수 시드·신호 조건으로 재탐색 보급률 30%와 100%를 비교할 수 있다. 이는 실험 제안이며 개선 결과가 이미 나온 것은 아니다. 전체 평균만으로 혜택의 분배를 판단하지 않고, 재탐색 차량/그 밖의 차량의 이동시간 분포와 p95, 도착률·미도착 수를 함께 본다. 시스템 최적 또한 차량별 희생을 없애는 기준은 아니므로 총 지연과 집단 간 차이를 구분한다. E4는 별도 SUMO 계획의 범위이며, 현재 Python E1~E3가 이 문제를 해결했다고 주장하지 않는다.
