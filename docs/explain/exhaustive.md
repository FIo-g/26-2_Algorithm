Exhaustive search explores every simple path (one that never visits a vertex twice) from the start to the destination without pruning, then selects the shortest among them. Excluding the cell it just came from, each inner grid cell offers up to 3 choices per step. Thus, for a path of length $L$, the branching factor makes the number of paths grow exponentially, remaining at most about $3^L$ (because cells cannot be revisited). In practice, as the grid grows by one row and column, the multiplier for the number of paths gets progressively larger, causing the path count to scale as $c^n$ ($c > 1$) with respect to the number of vertices $n$. In our measurements, the $5 \times 5$ grid finished almost instantly, whereas counting the paths in the $6 \times 6$ grid alone took 10.7 seconds, and the $7 \times 7$ grid is expected to take over an hour as it has roughly 456 times more paths. In contrast, Dijkstra's algorithm does not count paths one by one; once it settles a vertex and fixes its shortest distance, that vertex is never revisited. Consequently, its execution time is proportional to the number of vertices and edges rather than the number of paths, running in $O((n+m) \log n)$.
