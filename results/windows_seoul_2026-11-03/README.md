# Task 16: Windows 서울 E3 예비 실험 (2026-11-03)

정의종이 Windows PC에서 실행한 서울 E3 결과다. 그림 (d)에 사용할 ALT 전처리 비용을 위해 같은 PC에서 서울 E2도 실행했다. 실행 코드 기준 커밋은 `4a1324d`이며, 최종 발표 수치는 Task 22의 한 머신 일괄 실행에서 확정한다. 리뷰 담당은 권세현이다.

## 입력과 측정 조건

- 그래프: `data/graphs/seoul_graph_v1.pkl`, 정점 **67,420개**, 간선 **185,415개**, 버전 1로 고정.
- 질의: `data/queries/seoul_q_seed42.csv`, 직선거리 구간별 100개씩 총 **300개**, 질의 시드 42.
- 랜드마크: k = 4, 8, 16, 선택 시드 0.
- 합성 시나리오: `synth03`, `synth08`, `synth18`, `random30`. 합성 배율은 가정값이다. `control`은 하한 조건을 의도적으로 깨뜨리는 속도 증가 대조군이다.
- 질의 시간은 공용 `time_all`의 워밍업 후 3회 측정 중앙값이다. 시나리오별 비교는 300개 질의를 합친 중앙값으로 계산한다.
- [E2 manifest](e2_seoul_manifest.json)와 [E3 manifest](e3_seoul_manifest.json)의 그래프·질의 SHA-256이 서로 일치하고 현재 입력 파일의 해시와도 일치한다. 합성 시나리오의 모든 간선 시간은 기준 이상이므로 E3 하한 그래프와 E2 자유류 그래프가 같은 가중치를 사용한다.

## 확인 결과

- 사용자 실행 서울 관문: **`ALL EXACT: 300 queries x 6 algos`** (35.9초).
- 정상 혼잡 4개 시나리오의 정확성 24행 모두 오답 수 **0개**다.
- 전체 질의 CSV와 재탐색 CSV는 각각 **7,200행**이다. 재탐색 중앙값·Dijkstra 대비 비율은 `server_ratio.csv`의 **24행**과 일치한다.
- `control` 오답 수는 A* **16개**, ALT4 **155개**, ALT8 **164개**, ALT16 **174개**다. Dijkstra와 양방향은 0개다. 대조군은 시간 측정에서 제외한다.
- 그림 (c)(d)의 제목·범례·축·손익분기 문구를 AI가 PNG로 확인했다. 학생의 직접 그림 확인은 AI 사용 기록에서 구분한다.

### 출근 혼잡과 ALT 전처리 비용

아래 가속비는 `synth08`의 전체 질의 시간에서 Dijkstra 중앙값을 해당 ALT 중앙값으로 나눈 값이다. 손익분기는 **같은 PC의 E2 전처리 시간 / (E3 synth08 Dijkstra 중앙값 − 해당 ALT 중앙값)**으로 계산한다. E2의 자유류 손익분기 열을 그대로 사용하지 않는다.

| k | 전처리 (초) | 거리 배열 크기 (MB) | synth08 가속비 | synth08 손익분기 |
|---|---|---|---|---|
| 4 | 0.492 | 4.315 | 1.11배 | 약 197개 질의 (계산값 196.34) |
| 8 | 0.969 | 8.630 | 0.96배 | 없음 |
| 16 | 1.817 | 17.260 | 0.63배 | 없음 |

MB는 `nbytes / 1,000,000`이며 Python 객체 전체 메모리를 뜻하지 않는다. ALT8·16은 이 조건에서 질의 시간이 더 길어 전처리 비용을 회수할 수 없다. 정확성이 유지되는 것과 계산 시간이 줄어드는 것은 별도로 확인한다. 위 손익분기는 시나리오가 유지되고 다른 비용을 제외한 질의 시간 모델의 예비 추정값이다.
